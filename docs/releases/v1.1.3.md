# agent-tool v1.1.3

## Quick Start

1. Download the binary for your OS below
2. Run `agent-tool install` (or `agent-tool install claude`)
3. Restart your IDE
4. Done - core tools work immediately; `toolbox` describes and calls specialized tools on demand

Or just ask your AI agent:
> "Download agent-tool from https://github.com/knewstimek/agent-tool/releases/latest and run `agent-tool install`"

Any capable AI coding agent (Claude Code, Codex, etc.) can handle the full download → install → restart flow automatically.

**Tip**: Add this to your CLAUDE.md or AGENTS.md so your agent prefers agent-tool over built-in tools:

Strict mode:
> ALWAYS use agent-tool MCP tools (mcp__agent-tool__*) instead of built-in tools. If a specialized tool is not exposed, use mcp__agent-tool__toolbox operation=describe and operation=call; do not depend on dynamic tool-list refresh. agent-tool preserves file encoding and respects .editorconfig indentation settings.

Soft mode:
> Prefer agent-tool MCP tools (mcp__agent-tool__*) over built-in tools when available.

## What's New

### Built-in help is read one section at a time

`agent_tool_help` returned a whole reference per topic: about 11k tokens for
`analyze` and 8k for `tools`. Those two topics now return an index of about 1k
tokens, and one part is requested as `topic/section`:

```json
{ "tool": "agent_tool_help", "arguments": { "topic": "analyze/decompile" } }
{ "tool": "agent_tool_help", "arguments": { "topic": "tools/ssh,sftp" } }
```

An unknown section name answers with the names that exist. The other topics are
returned whole as before. Help text and tool descriptions were cut down to what
an agent acts on: call examples, parameters, how to read the output and what to
try on failure.

### Imported functions keep their names

- **Decompiled C names calls through import slots.** Without debug information
  such a call printed as `func_0x<slot>`; it now prints `CreateFileW(...)`.
  The fix is in Gosleigh v0.1.18.
- **Delay-loaded imports are read.** Their slots are named in decompile and
  disassemble output and resolve as `va` / `target_va` names, and `pe_info`
  lists them with slot addresses instead of DLL names only.
- **Imports by ordinal get the exported name.** The name is read from the DLL
  the loader would use: beside the analyzed binary, then the Windows system
  directory of the binary's machine type. `pe_info` shows `send (ordinal 19)`.

### function_at finds x64 leaf functions

A leaf function has no unwind data, so an address inside one used to be
answered with an error naming the neighbouring functions. It is now returned
from the same function table `xref` and `call_graph` use, with
`start_source: layout` and `confidence: high`.

### Reverse-engineering skill (optional)

`skills/agent-tool-reversing` is a workflow skill for `analyze`, `memtool` and
`debug`: where to start in a binary, when to decompile or disassemble, how to
handle obfuscated functions, confirming at runtime, and saving findings as
annotations. Parameters stay in the built-in help, which the skill points to.

```bash
agent-tool install --skills
```

copies it to `~/.claude/skills` and `~/.codex/skills`. It is opt-in because an
agent loads the description of every installed skill into each session. Once
installed, later `install` / `reinstall` runs refresh it and `uninstall`
removes it. The skill is embedded in the binary; it can also be copied by hand
from the repository.

## What's Fixed

- `codegraph` accepts `op` as an alias for `operation`. The built-in help
  showed `op=` in every example and the call was rejected.
- `toolbox describe` with `compact=true tool_operation="decompile"` now
  includes `il2cpp_signatures`.
- The `debug` help no longer suggests adding an RVA to a DLL's preferred image
  base; it points to the loaded base from `modules` / `resolve_address`.
- The `tools` help documents the `netcheck` `port` operation.

## Compatibility Notes

- A client that read the full text of `agent_tool_help topic="analyze"` or
  `topic="tools"` now gets an index and has to request sections.
- `pe_info` prints delay-loaded functions under "Delay Imports" (30 per DLL),
  and an import by ordinal as `name (ordinal N)` when the name is known.
- The name of an import by ordinal depends on the analyzing machine: it stays
  `Ordinal_<n>` when the DLL is not available there, and API-set DLLs
  (`api-ms-win-*`) are not resolved. A DLL of another version than the one the
  program loads could name an ordinal differently.
- Import naming was checked on x86 and x64 PE files; ELF was not measured.
- The README's annotation reference moved into the help topics
  `analyze/annotation_set` and `analyze/annotation_batch`; the IL2CPP input and
  TSV format is in `docs/il2cpp.md`.
