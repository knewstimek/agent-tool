# agent-tool v1.1.1

## Quick Start

1. Download the binary for your OS below
2. Run `agent-tool install` (or `agent-tool install claude`)
3. Restart your IDE
4. Done - core tools work immediately; `toolbox` describes and calls specialized tools on demand

Or just ask your AI agent:
> "Download agent-tool from https://github.com/knewstimek/agent-tool/releases/latest and run `agent-tool install`"

Any capable AI coding agent (Claude Code, Codex, etc.) can handle the full download → install → restart flow automatically.

**Tip**: Add this to your CLAUDE.md or AGENTS.md so your agent prefers agent-tool over built-in tools:

Strict mode:
> ALWAYS use agent-tool MCP tools (mcp__agent-tool__*) instead of built-in tools. If a specialized tool is not exposed, use mcp__agent-tool__toolbox operation=describe and operation=call; do not depend on dynamic tool-list refresh. agent-tool preserves file encoding and respects .editorconfig indentation settings.

Soft mode:
> Prefer agent-tool MCP tools (mcp__agent-tool__*) over built-in tools when available.

## What's New

### Decompiler: stack tracking after calls

Calls to functions without a debug prototype left the stack pointer
unrestored on x64 (and on x86 GCC/Go builds). Every stack access after the
first call drifted by the return address: return-address stores, `puVar + -8`
chains, `unaff_XMM` saves, and stack arguments read as locals. The host now
gives the decompiler the stack purge Ghidra's analysis would: 8 on x64, and on
x86 4 plus the callee's `ret N` (left unknown when no `ret` is reachable). On a
large IL2CPP game binary, the affected functions now match the output of
Ghidra's C++ decompiler core.

### Decompiler: Gosleigh v0.1.12 enhanced preset

decompile now applies Gosleigh's enhanced preset: extensions beyond Ghidra
that, on real-binary golden measurements, changed no function Ghidra already
decompiles correctly. They recover call arguments that Ghidra's core drops,
most visibly float arguments passed in XMM registers, and arguments a callee
reads even when the caller's code builds them across several pieces, and
float return values in XMM0. New extensions join the preset in Gosleigh, so
no new parameters appear here.

### Decompiler: `noreturn_verify`

Non-returning functions are still detected as in Ghidra, including the vote:
a callee with 3 or more call sites followed by padding or another function is
treated as non-returning. A frequently called function can meet that vote by
accident (3 `call; int3` sites among thousands of normal ones), and every
caller then loses the code after the call. When that happens the output now
warns and names the callee. `noreturn_verify=true` keeps such a callee
returning when its own code reaches a `ret`.

### Disassembly

- Switch tables placed inside the code (MSVC x64 puts them after the function
  body) print as one data line with their case targets, instead of being
  decoded as instructions that also misalign the code after them. The MSVC
  two-level form (a byte index table followed by the entry table) is
  resolved on x86 and x64. `instruction_search` and `xref` use the same
  resolver, so these switches now resolve there too.
- Disassembling from an address past the switch's dispatch jump (the tail of
  a function, the next page of a long listing) finds the tables too: inside
  an x64 `.pdata` range the code from the range start is scanned first.

## Breaking Changes

- `analyze` `disassemble`, `memtool` `disasm` and `debug` `disassemble` no
  longer print the hex encoding column by default. It took about half of each
  line. Pass `show_bytes=true` when you need the bytes (patching, signatures).
  Raw bytes alone remain available through `analyze` `hexdump` and `memtool`
  `read`.

## What's Fixed

- `instruction_search` with `register` and `displacement` never matched a
  register used as the memory base: `register=RSP displacement=0xf8` found
  nothing for `call [rsp+0xf8]`. With a displacement, the register now also
  matches that operand's base or index. Naming RSP/ESP lifts the default
  exclusion of stack-based operands.
- `call_graph` on obfuscated x64 code listed hundreds of callees taken from
  junk bytes behind opaque predicates. With `.pdata`, each function's walk
  stays inside its own ranges, and direct calls to addresses that are not a
  known function start are listed separately under "Not shown". x86 has no
  `.pdata` and is unchanged.
- `memtool` `disasm`'s truncation hint pointed at `analyze` parameters
  (`va=`, `offset=`, `stop_at_ret`); it now says `address=`.
