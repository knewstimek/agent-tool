# agent-tool v1.0.1

## Quick Start
1. Download the binary for your OS below
2. Run `agent-tool install` (or `agent-tool install claude`)
3. Restart your IDE
4. Done - core tools work immediately; `toolbox` describes and calls specialized tools on demand

Or just ask your AI agent:
> "Download agent-tool from https://github.com/knewstimek/agent-tool/releases/latest and run `agent-tool install`"

Any capable AI coding agent (Claude Code, Codex, etc.) can handle the full download → install → restart flow automatically.

**Tip**: Add this to your CLAUDE.md or AGENTS.md so your agent prefers agent-tool over built-in tools:

Strict mode:
> ALWAYS use agent-tool MCP tools (mcp__agent-tool__*) instead of built-in file tools. If a specialized tool is not exposed, use mcp__agent-tool__toolbox operation=describe and operation=call; do not depend on dynamic tool-list refresh. agent-tool preserves file encoding and respects .editorconfig indentation settings.

Soft mode:
> Prefer agent-tool MCP tools (mcp__agent-tool__*) over built-in file tools when available.

## What's New

This release trims the tool set to 40 tools and makes binary cross-references,
function bounds and instruction search substantially more complete and faster.

### Tool set: 55 -> 40 (breaking)

- `query` replaces `jsonquery`, `yamlquery` and `tomlquery`: one tool, format from the extension
  (.json, .yaml/.yml, .toml) or `format`; a UTF-8 BOM is accepted.
- `netcheck` replaces `externalip`, `dnslookup`, `tlscheck` and `portcheck`:
  `operation` = `external_ip`, `dns`, `tls` or `port`.
- Removed: `backup`, `compress`, `decompress`, `find_tools`, `sysinfo`, `envvar`, `firewall`,
  `webfetch`, `websearch`, `ipc`. `bash` and `httpreq` cover them, and agent clients have their
  own web search.
- The full tool list shrinks from about 86 KB to 73 KB; `core` and `core-lite` are unchanged.

### xref

- Every reference names its function: `0x...: CALL ...  ; in Class::Method+0x42`, using PDB bounds
  or the call_graph function table; the summary counts the functions.
- Stored pointers in data: vtable slots (with the slot index), function and callback tables. PE
  slots are checked against the relocation table; ELF PIE pointers come from RELATIVE relocations.
  Virtual functions that used to show "no references" now show their vtable slot.
- Immediates and absolute operands are decoded generically (`mov reg, imm`, `push imm`,
  `mov rax, imm64`, x86 `[abs32]`); `lea/mov reg, f` followed by `call reg` is reported as a call.
- Computed references: x64 tables and arrays read through the image base
  (`lea r, [__ImageBase]` ... `[r+index*scale+RVA]`), and for a switch case block, the dispatch
  jump whose table leads to it.
- `target_text`: the stored strings (UTF-8 and UTF-16LE) containing a text, and the references to
  each.
- `field=Class::member`: the member's offset from the PDB or DWARF (inherited members included);
  candidate functions with a `[reg+offset]` operand are decompiled and the ones whose C names the
  member are reported with the lines.
- xref accepts `pdb_path` and `pdb_force`.

### Function bounds and call_graph

- `.pdata` ranges stay exact, split-off cold blocks belong to their function, and functions
  without unwind data (x64 leaf functions, all of x86) are found by following each body's control
  flow across the code layout. Measured against PDB procedure bounds, the containing function is
  now right for 100% of addresses in a 78 MB x64 image (was 74%) and 99.5% in a 7 MB x86 image
  (was 39%). Decompile output is unchanged.
- call_graph callers are matched at every byte offset; tail jumps are marked, callers through a
  thunk are listed "via thunk", and functions reached only indirectly list the data slots that hold
  them.

### instruction_search

- Faster and complete on large images: value tracing runs per basic block in parallel and only in
  the functions holding the value, and the last binary's analysis stays cached. On a 78 MB x64
  image an immediate search went from about 61 s (incomplete) to about 4 s, and under 1 s for the
  next search. `trace_scope=all` traces every function, also finding values computed from other
  constants.
- Correctness: findings are confirmed only on converged loop states; x86 callees that pop their
  arguments (`ret N`) are modeled, with import sizes read from the imported DLLs (forwarders and
  API sets followed), so stale arguments of earlier calls are no longer reported.
- Switch dispatches (MSVC and GCC/Clang x64, x86 jump tables) are followed into their case
  blocks.
- `displacement=0x410` finds `[reg+0x410]` operands; hits are named by function; import calls are
  shown as `dll!Function`.

### Decompile

- `pdb_force=true` (with `pdb_path`; `decompile-all -pdb-force`) loads a PDB whose GUID does not
  match the image, or into an image whose debug record was wiped. Output carries a warning and
  `function_at` reports low confidence.

### Fixes

- golang.org/x/arch x86asm returns 32-bit displacements zero-extended
  ([golang/go#8000](https://github.com/golang/go/issues/8000)); backward RIP-relative references
  were missed or miscomputed in xref, disassemble names and instruction_search. All uses now
  sign-extend.

## Compatibility

- Breaking: the removed and merged tools above. Calls to `jsonquery`/`yamlquery`/`tomlquery` move
  to `query`; `externalip`/`dnslookup`/`tlscheck`/`portcheck` move to `netcheck`.
- New optional parameters only otherwise (`target_text`, `field`, `displacement`, `trace_scope`,
  `pdb_force`).
