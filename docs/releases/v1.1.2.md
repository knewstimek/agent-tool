# agent-tool v1.1.2

## Quick Start

1. Download the binary for your OS below
2. Run `agent-tool install` (or `agent-tool install claude`)
3. Restart your IDE
4. Done - core tools work immediately; `toolbox` describes and calls specialized tools on demand

Or just ask your AI agent:
> "Download agent-tool from https://github.com/knewstimek/agent-tool/releases/latest and run `agent-tool install`"

Any capable AI coding agent (Claude Code, Codex, etc.) can handle the full download → install → restart flow automatically.

**Tip**: Add this to your CLAUDE.md or AGENTS.md so your agent prefers agent-tool over built-in tools:

Strict mode:
> ALWAYS use agent-tool MCP tools (mcp__agent-tool__*) instead of built-in tools. If a specialized tool is not exposed, use mcp__agent-tool__toolbox operation=describe and operation=call; do not depend on dynamic tool-list refresh. agent-tool preserves file encoding and respects .editorconfig indentation settings.

Soft mode:
> Prefer agent-tool MCP tools (mcp__agent-tool__*) over built-in tools when available.

## What's New

### Session directory aliases

Register local or remote directories with `directory_alias` through `toolbox`,
then reuse paths such as `@src/server.go` in supported file operations.
Read, write, edit, copy, multiread and SFTP path metadata use a shorter alias
when it can be copied back into a later request.

Aliases stay in MCP session memory. Local aliases are scoped to the workspace;
remote aliases are scoped to the connection identity and work in SSH
`remote_root` and SFTP paths. No alias JSON file is created or loaded. Changing
an existing binding requires `overwrite=true`; `list` shows mappings on demand.

Aliases expand structured path arguments only. File contents and SSH command
text are preserved. Use `./@name` for a literal filename starting with `@`.
Aliases are path conveniences, not filesystem sandboxes.

### Reusable SSH and SFTP working roots

Set `remote_root` in a connection profile or request and reuse the returned
`connection_id` across SSH and SFTP within the same MCP session. Relative SFTP
paths resolve against that root; generated path metadata inside working roots
uses relative paths. Explicit absolute paths continue to work.

SSH sets the working directory separately from parsing the command, preserving
command syntax and stopping execution if directory setup fails. Set
`remote_shell` to match the server's interpreter when needed.

### Native IL2CPP extraction and typed calls

For Windows x64 images without debug information, `analyze` `decompile` accepts
`il2cpp_signatures`: `global-metadata.dat`, an Il2CppDumper `script.json`, or an
exported `methodsigs.tsv`. Adjacent sidecars take priority; otherwise standard
Unity metadata locations are discovered automatically. Multiple metadata files
require an explicit path; `none` disables this source. `decompile-all` uses the
same extraction and also supports `-il2cpp-signatures`.

Native extraction supports metadata v39 on Windows x64 PE. It reads method
addresses, shared-generic aliases, signatures, instance fields and virtual slots
directly in Go. No .NET runtime, LibCpp2IL installation or external dumper is
required, and the input DLL is never executed. Extraction stays in worker memory;
metadata changes invalidate reuse. No C# declarations or metadata dump files are
generated. Other metadata versions require external signature exports.
Automatic detection requires recognizable runtime exports. If automatic
extraction is unavailable, a note explains the fallback to inferred prototypes;
an explicitly selected invalid metadata file reports an error.

Known parameter and return types take precedence over inference. PDB/DWARF
still takes priority, function names stay unchanged, and unsupported types or
conflicting shared-generic signatures remain unlocked. TSV exports may include
a binary SHA-256 header to reject mismatched images.

Native class types apply when the runtime's virtual-method accessor reveals the
vtable offset; an unrecognized accessor leaves direct signatures available.
For external TSV exports, an optional sibling `il2cpp-types.json` supplies class layouts and
virtual-slot signatures using stable method IDs. Virtual prototypes apply
where the object's class type reaches the indirect call. The file must match
the binary hash declared by the TSV; runtime offsets must come from verified
layout data. Unknown slots and hidden-return-buffer signatures stay inferred.
Closed generic value layouts are not guessed. Interface dispatch helpers are
outside this type-chain support. See
[the export contract](https://github.com/knewstimek/agent-tool/blob/v1.1.2/docs/il2cpp-types.md).

## What's Fixed

- Gosleigh v0.1.16 improves inferred stack arguments, virtual-call wrappers and
  float-only callees. A later register-zeroing instruction no longer hides an
  argument already passed to an earlier call.
- Reused outgoing stack slots, stale high bytes and MSVC exception-handling
  state are less likely to become extra call arguments or invent preceding
  register arguments.
- Locals filled through output parameters retain their initialization. Struct
  copies folded into loops retain the callee-filled value instead of appearing
  to keep an old zero or uninitialized value.
- Pointers and address calculations retain their pointer types when stack
  storage is also reused for floating-point temporaries, reducing misleading
  bit casts in field accesses.
- Floating-point grouping is preserved, including `a * (b * c)`, so generated
  C does not introduce different float32 rounding by reassociating expressions.
- Floating-point comparisons preserve NaN branch behavior. Normalized switch
  dispatches retain their case values, and dynamic stack allocation no longer
  produces spurious return-address stores around calls.
- PE/ELF executable-section flags reach callee analysis, keeping data and import
  slots from being analyzed as instructions.
- Workspace and alias mappings stay consistent throughout a multi-path call,
  including when another request changes a binding. File path whitespace is
  preserved.
- Aliases, persistent shells, pooled SSH/SFTP connections, connection handles
  and background-job access are isolated between MCP sessions. SFTP status
  uses current aliases and falls back to exact remote paths after rebinding.
- SFTP downloads reject protected destinations reached through final symlinks
  or symlinked ancestors, including new child paths. Windows checks recognize
  case and trailing-dot/space variants of sensitive paths.

## Compatibility Notes

Generated path metadata may now be relative or use a reusable directory alias.
Consumers that parse tool output should accept these forms. File contents and
remote command output are not rewritten.

Connection, shell and job handles belong to the MCP session that created them;
another client must create its own resources. Directory aliases disappear when
the session ends. Existing IL2CPP TSV columns and existing tool parameters
remain supported.
