# agent-tool v1.0.5

## Quick Start
1. Download the binary for your OS below
2. Run `agent-tool install` (or `agent-tool install claude`)
3. Restart your IDE
4. Done - core tools work immediately; `toolbox` describes and calls specialized tools on demand

Or just ask your AI agent:
> "Download agent-tool from https://github.com/knewstimek/agent-tool/releases/latest and run `agent-tool install`"

Any capable AI coding agent (Claude Code, Codex, etc.) can handle the full download → install → restart flow automatically.

**Tip**: Add this to your CLAUDE.md or AGENTS.md so your agent prefers agent-tool over built-in tools:

Strict mode:
> ALWAYS use agent-tool MCP tools (mcp__agent-tool__*) instead of built-in tools. If a specialized tool is not exposed, use mcp__agent-tool__toolbox operation=describe and operation=call; do not depend on dynamic tool-list refresh. agent-tool preserves file encoding and respects .editorconfig indentation settings.

Soft mode:
> Prefer agent-tool MCP tools (mcp__agent-tool__*) over built-in tools when available.

## What's New

This release improves the core file tools: local indentation recovery, legacy
encodings, mixed line endings, bounded multi-file reads, and visible write failures.

### Edits follow the style at the actual location

When an agent supplies spaces for tab-indented code, or a file mixes several
styles, whitespace recovery uses the matched line or block's actual prefixes.
It preserves known nesting, alignment and indented blank lines instead of
forcing every region to the file-wide majority style.

- Content-based style detection samples up to 8 MiB without a fixed line-count
  cap, supports long lines and LF/CRLF/CR, and separates block-opening evidence
  from continuation alignment.
- C++/header and Python edits reuse the existing embedded Tree-sitter WASM
  engine. Direct statements in the actual enclosing block supply space-width
  evidence, avoiding misleading nearby functions, nested sibling blocks and
  aligned argument lists.
- In successfully parsed replacement snippets, lines aligned to an actual
  inline token keep that alignment. Hanging continuations still scale by
  indentation level, even when the first argument is on the opening line.
  Multiline string and comment interiors retain their supplied content.
- `multiedit` gains `indent_style` parity with `edit`, and each operation sees
  the previous operation's result and current style.
- Exact matches and explicit style overrides keep their existing behavior.
  Equally plausible recovery matches require more context.

No new external compiler, Python installation, CGO dependency or code index is
required. Syntax assistance falls back to the existing heuristic when the
relevant block is erroneous or inconclusive, analysis fails or times out, or
the source exceeds 8 MiB. Replacement-snippet assistance is limited to
64 KiB/512 lines. It is not a full formatter or a guarantee of semantic equivalence.

### Read and edit legacy text with an explicit encoding

`read`, `edit`, `multiedit`, `write`, `patch`, `file_info` and `regexreplace`
accept an `encoding` override. `multiread` accepts a default encoding and
per-file overrides. CP949 aliases include `windows-949` and `UHC`.

For example, retry a legacy file without changing project-wide settings:

```text
read(file_path="src/example.cpp", encoding="CP949")
edit(file_path="src/example.cpp", encoding="CP949",
     old_string="old_value", new_string="new_value", dry_run=true)
```

An explicit encoding overrides EditorConfig; an existing BOM takes priority.
These parameters select how to read the source, rather than converting the file.

- Legacy detection samples after a long ASCII preamble, so headers do not hide
  the non-ASCII body.
- Malformed UTF-8/UTF-16 and detected lossy decoding return actionable errors.
  Genuine replacement characters and valid supplementary UTF-16 characters
  remain supported.
- EditorConfig properties inherit independently across parent files, including
  `unset`, `root`, `tab_width`, `indent_size=tab`, and common recursive path
  patterns. New files honor `charset=utf-8-bom`.

### Consistent line ranges and resumable multi-file reads

`read`, `multiread`, `file_info`, `grep` and `patch` agree on LF, CRLF and bare-CR
line boundaries, without inventing a final empty line.

- Reading past EOF returns no rows. Combined offsets/end lines stay within the
  requested range; fractional or overflowing ranges are rejected.
- `multiread` reports `start_file_index` and `resume_offset` for continuation.
  Reuse the same original file list. The resume offset applies only to that
  file's original window, leaving later files' ranges unchanged.
- Tight output budgets keep errors visible and provide progress when the first
  line is oversized. Long-line truncation avoids copying the entire line into
  a rune array.
- `grep` in `files_with_matches` mode searches beyond long lines and reports
  scan failures.

### Preserve originals when a save fails

Text writes no longer fall back to truncating the original in place if staging
or atomic replacement fails. Locked/read-only-file failures preserve the
original and clean up staged files.

Editing handlers capture the raw hash with the decoded source and recheck it
before saving. Same-path helper writes are serialized, so a stale helper
snapshot is rejected. `edit`, `multiedit` and `patch` also accept
`expected_hash` for caller-supplied conflict checks. This is not an atomic
filesystem compare-and-swap against uncooperative external writers.

### Clearer bulk replacement, patch, diff and conversion results

- Directory `regexreplace` reports per-file failures, bounded error samples,
  scan counts, matching-file cap hits and output truncation. An all-failed scan
  returns an error. Successful files remain changed when another file fails:
  retry only failed paths, especially for non-idempotent replacements.
  `max_files` limits matching files to change or preview; hitting the cap does
  not prove another match exists.
- Regex replacements without literal newlines in the replacement template avoid
  collecting every match-index slice, while preserving captures and zero-width
  matches and keeping previews bounded.
- `patch` fixes zero-context insertion boundaries, including empty files, retains
  header-like hunk data and CR endings, and checks declared hunk counts before
  writing. A failed `multiedit` batch leaves the file unchanged.
- `diff` distinguishes equal decoded text from equal raw bytes, reports
  encoding/BOM and mixed-ending placement differences, and identifies
  missing-final-newline changes. It adds `encoding_a`/`encoding_b`, honors
  `context_lines=0`, and bypasses the changed-text line cap for identical text.
- `convert_encoding` adds `from_encoding` and CP949 target aliases, keeps GBK
  distinct from GB18030, and rejects unrepresentable target characters without
  modifying the original. GB2312 remains an explicit GBK compatibility alias.
