# agent-tool v1.1.0

## Quick Start

1. Download the binary for your OS below
2. Run `agent-tool install` (or `agent-tool install claude`)
3. Restart your IDE
4. Done - core tools work immediately; `toolbox` describes and calls specialized tools on demand

Or just ask your AI agent:
> "Download agent-tool from https://github.com/knewstimek/agent-tool/releases/latest and run `agent-tool install`"

Any capable AI coding agent (Claude Code, Codex, etc.) can handle the full download → install → restart flow automatically.

**Tip**: Add this to your CLAUDE.md or AGENTS.md so your agent prefers agent-tool over built-in tools:

Strict mode:
> ALWAYS use agent-tool MCP tools (mcp__agent-tool__*) instead of built-in tools. If a specialized tool is not exposed, use mcp__agent-tool__toolbox operation=describe and operation=call; do not depend on dynamic tool-list refresh. agent-tool preserves file encoding and respects .editorconfig indentation settings.

Soft mode:
> Prefer agent-tool MCP tools (mcp__agent-tool__*) over built-in tools when available.

## What's New

### Long-running calls no longer block the agent

An MCP tool call blocks the agent until it returns, so a slow build or scan
left the agent unable to answer or do anything else. Calls that are still
running after about 15 seconds now return a `job_id` while the work continues
in the background.

This applies to `bash`, `ssh`, `sftp`, `download`, `analyze`, `codegraph`, and
`memtool`. Collect results with
`toolbox operation=job job_action=wait job_id=<id>`. Other actions are
`status`, `tail`, `cancel`, and `list`. Cancelling a wait only stops the
waiting; the job keeps running. `job_action=cancel` stops the work itself.

### procexec jobs

- A run waits up to `yield_after_sec` (default 15) and then returns a `job_id`.
  `operation=wait|status|tail|cancel|list` manage it.
- Cancel and timeout kill the whole process tree. On Windows this uses a job
  object, so it also reaches grandchildren whose parent has already exited.
- Timed-out runs report `timed_out` with the output captured so far.
- A requested cancel is reported as a success, and cancelling a job that has
  already finished returns its result instead of an error.
- Passing `tail_lines` to `wait` or `status` returns only the tail of a
  finished job, which keeps progress-refresh output (watch loops, progress
  bars) from being replayed in full.
- `background=true` now captures stdout/stderr to log files reported in the
  result. The process still survives an agent-tool restart.

### ssh jobs

Background SSH jobs share the same job registry. They gain `operation=wait`,
appear in `toolbox operation=job job_action=list`, and a finished job's
status or wait includes its output.

## Breaking Changes

- `procexec` `timeout_sec` is now the process lifetime limit (default 600,
  max 7200), not how long the call blocks. Use `yield_after_sec` to control
  blocking. Background runs have no implicit limit.
- `bash`: a call on a session whose previous command is still running now
  fails immediately with guidance to use another `session_id`, instead of
  queueing behind it. `memtool` sessions behave the same way.

## What's Fixed

- `memtool` scans ignored cancellation and kept running after the client gave
  up. Search, filter, struct search, pointer scan, snapshot, and diff now stop
  promptly. A cancelled filter is rolled back, so the session keeps its
  previous matches.
- `ssh` `powershell_script` on non-English Windows returned garbled output
  and PowerShell progress noise. Output is now UTF-8 and progress records are
  suppressed. Staging also works when the remote temp path contains non-ASCII
  characters.
- `codegraph` applies its SQLite settings to every pooled connection and waits
  briefly on a busy database instead of failing. Cancelling an index keeps the
  files already indexed. A second concurrent index of the same project is
  refused with guidance.
