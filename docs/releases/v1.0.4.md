# agent-tool v1.0.4

## Quick Start
1. Download the binary for your OS below
2. Run `agent-tool install` (or `agent-tool install claude`)
3. Restart your IDE
4. Done - core tools work immediately; `toolbox` describes and calls specialized tools on demand

Or just ask your AI agent:
> "Download agent-tool from https://github.com/knewstimek/agent-tool/releases/latest and run `agent-tool install`"

Any capable AI coding agent (Claude Code, Codex, etc.) can handle the full download → install → restart flow automatically.

**Tip**: Add this to your CLAUDE.md or AGENTS.md so your agent prefers agent-tool over built-in tools:

Strict mode:
> ALWAYS use agent-tool MCP tools (mcp__agent-tool__*) instead of built-in file tools. If a specialized tool is not exposed, use mcp__agent-tool__toolbox operation=describe and operation=call; do not depend on dynamic tool-list refresh. agent-tool preserves file encoding and respects .editorconfig indentation settings.

Soft mode:
> Prefer agent-tool MCP tools (mcp__agent-tool__*) over built-in file tools when available.

## What's New

### Decompile keeps functions that contain undecodable bytes

One undecodable instruction -- junk bytes from obfuscation, or a branch into
unmapped memory -- used to fail the whole function with an engine error. Now only
that path ends, as in Ghidra:

```c
int guarded(int x) {
    if (x < 1) {
        /* WARNING: Bad instruction - Truncating control flow here */
        halt_baddata();
    }
    return x * 3 + 1;
}
```

The decode error is still listed as a `// warning:` line. Unimplemented
instructions likewise end in `halt_unimplemented()` instead of cutting off the
rest of the function.

### Obfuscated functions decompile within their .pdata extent

With junk bytes behind opaque predicates, following both sides of every branch
makes the flow explode: Ghidra 12 times out after 300 s on such functions, and
agent-tool used to hit the 2 GB worker heap limit after minutes. Now a flow over
the instruction limit is retried inside the function's exact x64 `.pdata` extent
(its own range plus split-off fragments). Each place flow leaves it is marked, and
the rest of the function prints:

```c
        /* WARNING: Function flow out of bounds: r0x7ff7014b1197 flows to r0x7ff7014b2d68 */
        halt_missing();
```

Code inside the extent can still contain junk paths (`halt_baddata()`): static
analysis cannot tell an opaque predicate in obfuscator-made code from a real
branch with certainty. Where a runtime trace has established which side a
conditional jump takes, pass it in:

```
analyze(operation="decompile", file_path=..., va="0x140012340",
        assume_branches="0x140012375=taken,0x1400123a2=fallthrough")
```

Each listed jump is fixed to that side before the flow is followed (as if patched
to `jmp` / `nop`) and marked in the C; addresses no decompiled flow reached are
listed. Without `.pdata` (x86, leaf functions) a runaway flow fails at once with
"Flow exceeded maximum allowable instructions" and the number of paths that hit
undecodable bytes. The same error now ends a function whose own code exceeds the
20,000-instruction limit, where earlier versions printed a silently cut-short flow.

A function that kills the decompile worker (memory or crash) no longer costs the
other functions of the same call: they continue on a fresh worker.
(Gosleigh v0.1.7 - v0.1.10.)

### disassemble says why it stopped at a function end

`disassemble va=...` stops at the function end it finds, but the output used to
end there without explanation:

- At the end of an x64 `.pdata` range of a split function (MSVC hot/cold code),
  it lists the function's other ranges to disassemble, and names the owning
  function when `va` was inside a split-off fragment.
- At a heuristic end (no `.pdata`, e.g. x86), it says the end is an estimate and
  where to continue.

### Startup profiles take extra tools

Append `+tool` names to a preset to expose specific tools at startup:

```
agent-tool --profile core+copy+delete+ssh+wintool
```

The same syntax works in `AGENT_TOOL_PROFILE` and toolbox `operation=profile`.
An unknown tool name or an empty component rejects the whole selection before any
tool is registered.
